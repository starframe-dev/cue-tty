# Восстановление сборки и стабильности cue-tty

## Контекст

Аудит актуального клона на `275667058500d7bedb6618824e7ec25588f23ed8` подтвердил блокирующие дефекты: основной модуль ссылается на недоступный placeholder Portalis и локальный `replace`; модуль Warp содержит локальный абсолютный путь; `.gitignore` исключает `cmd/cuetty-cli`, в котором отсутствует tracked entrypoint. В ANSI parser символ `^` ошибочно начинает ESC-последовательность. Handoff дополнительно перечисляет возможные дефекты ядра PTY, App, сессий, безопасности, CLI и терминальной совместимости — они требуют проверки по актуальному исходному коду до изменений.

Доступный Portalis upstream: `github.com/starframe-dev/portalis`, HEAD `4d6e28d0f8f02fe1947f5e3efc6429138ffb5818`, `go 1.26.8`. Доступный Warp upstream: `github.com/starframe-dev/warp`, HEAD `a04f863abd9b8206092ce362701a34cee7753a11`. Совместимость Portalis с текущими вызовами cue-tty ещё должна быть проверена.

## Цель

Сделать сборку воспроизводимой из чистого клона, восстановить запускаемый `cuetty-cli`, и исправить подтверждённые дефекты безопасности, конкурентности, PTY и эмуляции терминала без замены архитектуры `pty → ansi → cue → cli`. Каждое исправление сопровождается регрессионным тестом; итоговый статус определяется фактически пройденными критериями handoff.

## Что изменится

- `go.mod`, `go.sum` — версия Portalis без локального replace.
- `examples/warp-demo/go.mod`, `go.sum`, `e2e_test.go` — разрешение зависимостей без абсолютных локальных путей.
- `.gitignore`, `cmd/cuetty-cli/main.go` — устранение исключения источника и восстановление CLI/daemon/REPL запуска.
- Подтверждённые модули в `pkg/ansi`, `pkg/pty`, `pkg/cue`, `pkg/cli` и их тесты.
- `.github/workflows/` — проверки Linux и macOS, включая вложенный модуль.
- README и спецификации — только если выявленное поведение расходится с описанием.

## Детали реализации

1. Проверить актуальные Go API Portalis и Warp, установить доступные совместимые версии, удалить локальные `replace`; не маскировать недоступность зависимости.
2. Проверить полный исходный код и тесты по пунктам handoff, записать матрицу подтверждённых дефектов, затем исправлять в приоритете сборка/безопасность/корректность.
3. Восстановить `cmd/cuetty-cli/main.go`, исключить одноимённое правило `.gitignore` и обеспечить запуск CLI-команд, REPL и демона.
4. Исправить parser: печатный `^` остаётся символом; проверить границы CSI/SGR и память неполных последовательностей; добавить тесты произвольного chunking и fuzz target.
5. Для каждого подтверждённого дефекта PTY, сессий, безопасности и API добавить тест, проверяющий реальное поведение; не подменять реальные процессы и HTTP-сценарии фиктивными результатами.
6. Добавить CI Linux/macOS с командами handoff и отдельным запуском тестов `examples/warp-demo`.
7. Запустить обязательные проверки и записать точные результаты и причины всех невыполненных критериев; READY допустим только при выполнении требований релиза.

## Критерии приёмки

- [ ] Portalis API проверен по upstream исходникам; чистый основной модуль собирается без локальных путей.
- [ ] Warp nested module и E2E работают без локальных абсолютных путей.
- [ ] CLI entrypoint tracked Git и запускает CLI/REPL/daemon сценарии.
- [ ] Исправлены только подтверждённые дефекты; каждый исправленный дефект покрыт регрессионным тестом.
- [ ] Выполнены доступные команды `go mod tidy`, `go build ./...`, `go test ./...`, `go test -race ./...`, `go vet ./...`, `govulncheck ./...` и тесты Warp; результаты зафиксированы.
- [ ] При невыполнении любого критерия или блокере итог указан как NOT READY.
