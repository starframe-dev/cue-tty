# Финальные точечные исправления cue-tty

## Контекст
На audited HEAD `2b93a74048163c2e43f4fbbd4c7b72e2934b7095` подтверждены три проблемы:
1. PTY разрешает до 1 048 576 ячеек, а опубликованный Portalis v0.1.0 принимает максимум 262 144; из-за молчащего `Screen.Resize` PTY и экран расходятся.
2. `node` повторяет HTTP запросы до двух секунд для обычного TUI, у которого унаследованный FD 3 не обслуживается как HTTP listener.
3. `NodeTree.Render()` не показывает уже собранные ячейки и стили.

## Цель
Согласовать размеры PTY/Portalis и сделать ошибочные resize атомарными; ограничить node probe одним коротким HTTP запросом с возможностью повторного обнаружения поздно запущенного Warp; добавить подробный текстовый cell-view, не меняя существующий компактный Render и экспортированные поля NodeTree.

## Что изменится
1. `pkg/pty/pty.go` — общий максимальный размер 262 144 ячейки и предварительная валидация до spawn/resize.
2. `pkg/cue/app.go` и `pkg/ansi/screen.go` — вызвать проверяемый `ResizeChecked`, сохранив старый `Resize` API.
3. `pkg/cli/commands.go`, `pkg/cli/elements.go` — быстрый единичный HTTP probe, отрицательный результат не кешируется; `node --cells` запрашивает подробный screen view.
4. `pkg/cli/nodes.go` — добавить метод подробного вывода существующих NodeTree cells/styles; сохранить `Render()` и структуру NodeTree.
5. Тесты PTY/Cue/CLI/NodeTree, `README.md` и эта спецификация — граничные размеры, точность снимков, CLI режим и пользовательский лимит.

## Детали реализации
- Единый допустимый размер PTY/Cue: положительные dimensions, не более 4096 по каждой оси и не более `1<<18` (262 144) ячеек. Матрица: 80×24, 1024×128, 1024×256 — успех; 1024×257, 1024×1024, 0×24, 65536×24 — ошибка.
- Проверять размеры до `exec`/старта процесса. В `App.Resize` отклонять размер до ioctl; затем обновлять PTY и использовать `ansi.Screen.ResizeChecked` с теми же ограничениями Portalis. При любой validation/ioctl ошибке screen остаётся неизменённым; при валидном размере Portalis принимает те же границы.
- Сохранить существующую сигнатуру `ansi.Screen.Resize` как совместимый wrapper. Добавить проверяемый wrapper `ResizeChecked` и использовать его из `App.Resize`. CLI `resize` продолжает вызывать `App.Resize` и возвращает ошибку без сообщения об успехе.
- Убрать 2-секундные повторные попытки и `time.Sleep` из HTTP probe. Одна попытка ждёт HTTP response headers не более 100 мс; лимит чтения тела остаётся ограниченным. HTTP response любого статуса подтверждает наличие inspector; status/JSON/body ошибки возвращаются. До первого HTTP response timeout означает неподдерживаемый/ещё не готовый inspector и `node` возвращает screen tree. Отрицательный результат не кешируется: следующий `node` снова проверяет endpoint, поэтому поздно запущенный Warp обнаружится без произвольного ожидания. После подтверждения transport ошибки не маскируются fallback.
- Сохранить Bearer token на каждом `/elements` запросе и FD 3 listener handoff. `node --cells` явно пропускает HTTP inspector и выводит screen cells; обычный `node` сохраняет прежний компактный вывод и Warp element tree.
- Добавить `NodeTree.RenderCells()` без изменения `NodeTree.Render()` или существующих полей/сигнатур. Подробный вывод показывает row/column, rune, combining string, FG/BG и доступные в `CellNode` style attributes; default пустые клетки пропускаются, но выводятся продолжения wide characters и пустые клетки с цветом/стилем.

## Критерии приёмки
- PTY, App и CLI `resize` согласованы с максимумом Portalis; все заданные размеры имеют ожидаемый результат.
- Недопустимые размеры при `Launch` отклоняются до создания дочернего процесса; при неуспешном `Resize` PTY и screen сохраняют исходные размеры.
- Обычный TUI получает screen tree быстро, без 2-секундного retry loop.
- Поздно запущенный Warp определяется следующим `node`; ошибки подтверждённого inspector не переходят в fallback; токен/FD 3 работают.
- Компактный `Render()` не меняется; `node --cells` показывает фактические ячейки, стили, wide-cell continuation и combining marks, пропуская незаполненные default cells.
- Root tidy/build/test/race/vet/govulncheck и полный Warp E2E проходят; hosted Linux/macOS CI зелёный.
- Не изменены существующие публичные сигнатуры/поля и не добавлены дублирующие terminal implementations.
