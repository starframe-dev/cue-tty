# Финальные исправления после аудита cue-tty

## Контекст
На audited HEAD `f8b710436c0c7c50e32eaddef3158e4a6447d8f1` подтверждены три дефекта: зарезервированный для любого дочернего приложения HTTP listener заставляет `node` обращаться к `/elements` даже для обычного TUI; глобальный разбор `-s` повторно поглощает аргументы после имени команды; snapshots сессий захватывают тот же mutex, который удерживается на время долгих команд.

## Цель
Исправить три дефекта без изменения архитектуры PTY→ANSI→Cue→CLI, сохранить listener handoff через FD 3, bearer-token аутентификацию, текущий синтаксис CLI и работу Warp/Portalis. Добавить регрессионные и конкурентные тесты; READY разрешён только после полного локального набора проверок, Linux/macOS Warp E2E и зелёного hosted CI.

## Что изменится
1. `pkg/cli/session.go` — отдельная краткоживущая синхронизация состояния сессии; сохранить per-session сериализацию команд и безопасный FD 3 handoff.
2. `pkg/cli/commands.go` — распознавание доступного HTTP-инспектора в `node`; fallback на screen tree только до подтверждения HTTP-ответа; ошибки ответившего инспектора не скрывать.
3. `pkg/cli/daemon.go` — использовать явно названный `Session.commandMu` для сериализации команд; snapshots не захватывают эту блокировку.
4. `pkg/cli/repl.go` — не повторно разбирать исходные глобальные CLI-флаги при запуске интерактивного REPL.
5. `cmd/cuetty-cli/main.go` — выделить тестируемый парсер только для ведущих глобальных флагов `-s`, `--session`, `-s=...`, `--session=...`; после имени команды передавать остаток argv без изменений; поддержать `--`.
6. Тесты `pkg/cli` и `cmd/cuetty-cli` — обычный TUI/HTTP tree, ошибки доступного Warp-инспектора, независимые Warp и обычные сессии, быстрые `show/list` при `wait 60000`, конкурентный lifecycle, точный argv до тестового дочернего процесса.
7. `specs/final-release-fixes.md` — критерии и фактический результат проверки.

## Детали реализации
- Хранить отдельно адрес зарезервированного listener и факт подтверждённого HTTP-инспектора. `/elements` считается обнаруженным при получении HTTP-ответа; если до первого HTTP-ответа endpoint не отвечает, `node` строит `BuildNodeTree(session.Page)`. После подтверждения инспектора любые transport/status/JSON ошибки возвращаются диагностикой и не запускают fallback. Каждый запрос сохраняет `httpToken`; listener продолжает передаваться дочернему процессу через fd 3.
- Сохранить `Session.commandMu` для последовательного выполнения команд. Добавить отдельную блокировку короткого состояния; `Session.Snapshot` копирует имя/признак running/указатель приложения под этой блокировкой, затем получает screen snapshot из потокобезопасного `cue.App`. Записи состояния при launch/close защищаются ею. `SessionManager.Snapshots` не берёт command mutex и не держит mutex менеджера во время копирования экранов.
- Глобальные флаги разбираются только с начала argv и только до первого токена команды. `--` прекращает разбор флагов, после чего все токены, включая `-s`, `--session`, пустые строки, Unicode, пробелы, кавычки и специальные символы, остаются в исходном порядке. Отсутствие команды запускает интерактивный REPL для выбранной сессии.
- Отдельная регрессия запускает `wait 60000`, проверяет быстрый ответ обеих команд `show` и `list` со всеми сессиями, затем отменяет wait через штатный `close` и дожидается завершения.

## Критерии приёмки
- [x] Обычный TUI без HTTP отвечает на `node` screen tree; резервирование listener и токен не теряются.
- [x] Warp отвечает на `node` element tree с Bearer token; доступный endpoint с HTTP/JSON ошибкой даёт диагностируемую ошибку, не screen fallback.
- [x] Несколько независимых сессий Warp и обычного TUI работают параллельно без путаницы состояния.
- [x] Табличные и дочерние argv-тесты подтверждают точное сохранение аргументов после команды, включая `-s`, пробелы, Unicode, пустые значения, кавычки и спецсимволы; ведущие варианты `-s`, `--session`, `-s=...`, `--session=...` и `--` работают.
- [x] `show/list` быстро возвращают полные snapshots при активном `wait 60000`; race и lifecycle-тесты не находят data races, deadlocks и утечек процессов.
- [x] Отмена PTY-записи, управление процессами, listener handoff и мышь сохраняют существующее поведение и проходят регрессии.
- [x] `go mod tidy`, `go build ./...`, `go test ./...`, `go test -race ./...`, `go vet ./...`, `govulncheck ./...` прошли локально.
- [ ] Полный Warp E2E пройдёт на Linux и macOS в hosted CI. Полный локальный E2E на macOS уже прошёл без кэша (`go test -count=1 ./...` в `examples/warp-demo`).
